# 项目目标

> 规划基线：2026-10-20，用户提供《Windows Audio Manager 项目开发规划》（规划 V1.0）并要求纳入现有文档。原待确认的目标、技术栈和架构据此补充；以下是开发规划，不代表已经实现。

## 定位与目标

- 项目名称：Windows Audio Manager（暂定）；类型：Windows 桌面音频管理工具；目标平台：Windows 10 / Windows 11。
- 当前工作目录仍为 `G:\c#_code\MixDeck`，不改名；工程名称沿用 `AudioManager`。四项目及阶段 1～3 的核心、实时状态、WPF 界面和托盘已实现并在本机 Windows 11 完成功能验收，后续进度见 [STATUS.md](STATUS.md)。
- 面向需要管理各应用音量、保存配置并恢复音量的 Windows 用户，增强原生音量混合器的管理能力。
- 解决的使用问题：重启后音量配置变化、显示值与实际效果可能不一致、异常时需反复拖动滑块，以及缺少便捷的音量快照、备份和恢复机制。
- 最终目标：稳定控制各应用音量，保存用户设置并按需自动恢复，减少配置丢失和重复手动调整。配置保存与恢复是主要功能，v0.4 是首个满足主要使用需求的版本。

## 核心需求与范围

| 功能领域 | 规划范围 |
| --- | --- |
| 核心音频管理 | 枚举输出设备、识别默认设备；读取系统主音量及静音并调整主音量；枚举应用音频会话，读取应用名称、进程、音量和静音，独立调整应用音量及静音；识别同一应用的多个会话，处理退出后的会话消失 |
| 配置保存与恢复 | 读取可枚举会话，保存应用标识、音量、静音及输出设备信息；手动保存与恢复；自动恢复开关、重启登录后的恢复、尚未启动应用的延迟恢复；多个配置方案；防止异常实时状态覆盖用户目标配置 |
| 事件监听 | 监听会话创建、状态、音量及静音变化，以及默认设备变化、设备连接与断开；新会话匹配规则；设备变化后重建设备与会话监听；避免自身操作造成重复处理和事件循环 |
| 异常诊断与恢复 | 记录 API 音量并比较目标音量，检测可观察异常；手动重新应用、重新获取会话及刷新状态；记录修改、恢复及 API 结果；失败日志与错误提示；实验验证相同值重设、改变后再恢复等操作的实际效果 |
| 图形界面与驻留 | WPF 界面显示主音量、输出设备及正在使用音频的应用列表；显示应用图标、名称、音量，提供独立滑块及静音；保存与恢复入口、自动恢复开关和规则管理；托盘驻留与菜单、开机自启、异常及操作反馈 |
| 配置管理 | 本地 JSON 与可扩展结构；稳定应用匹配，按需区分输出设备；导入与导出、恢复默认配置、用户偏好；处理损坏、缺失字段和版本变化，安全写入与备份 |

必须区分三类状态：**实时状态**来自当前 Windows 音频会话，**已保存状态**由用户主动保存，**目标状态**由当前启用的恢复规则确定；不得混为一份可被实时回写覆盖的数据。

音频 API 返回的音量不等于最终听到的声音大小。应用内部音量、驱动和其他音频处理均可能影响播放效果；异常处理必须先复现、定位并验证策略，不承诺仅凭数值比较识别或修复全部音频异常。

## 技术栈与边界

| 类别 | 用户规划的选择 |
| --- | --- |
| 语言与平台 | C#、.NET 10 LTS；Windows 10 / Windows 11 |
| 界面 | WPF、XAML、MVVM |
| 业务架构 | 模块化单体、分层设计，通过依赖注入组合 |
| 音频管理 | Windows Core Audio API，优先使用 NAudio；封装不足时补充 C# COM Interop |
| 事件 | Windows 音频事件回调，优先事件驱动，避免持续高频轮询 |
| 配置 | JSON 文件、System.Text.Json |
| 日志 | Microsoft.Extensions.Logging |
| 测试 | xUnit；具备环境时开展 Windows 音频集成测试 |
| 版本与仓库管理 | Git、GitHub（均为计划，当前未建立仓库） |

模块职责、API、依赖和关键流程见 [ARCHITECTURE.md](ARCHITECTURE.md)。技术选择保持用户规划；阶段 1 验收见 [CORE_VALIDATION.md](CORE_VALIDATION.md)，阶段 2 实时事件、状态模型及监听重建见 [REALTIME_STATE_VALIDATION.md](REALTIME_STATE_VALIDATION.md)。阶段 3 的 WPF 界面已随事件实时同步并支持托盘；最新完整回归 116 项（含 9 项真实集成）全部通过，桌面实机证据及验证缺口见 [DESKTOP_VALIDATION.md](DESKTOP_VALIDATION.md)。配置恢复、跨系统兼容、长期运行和发布仍待后续任务，不据此认定正式版完成。

## 不可随意改变的原则

- 保留 Windows 原有音频系统，通过其公开音频管理接口增强控制；不替换系统音频引擎，不依赖修改系统文件。
- GUI、业务规则和 Windows 系统调用分离；Core 不依赖 WPF 或具体音频封装，UI 不直接操作音频 API。
- 音量规则与设备控制分离，实时状态与持久化配置分离；不能仅以 PID 作为持久化应用标识。
- 事件回调不得阻塞 UI；正确管理音频资源、COM 对象和订阅生命周期，避免全局共享可变状态。
- 核心目标、需求边界、技术栈及重大架构变更须经用户确认，不能为方便实现而自行改变。

## 首个正式版本完成标准

- 能管理当前可访问的主要输出设备，读取并调整各应用音量，正常处理设备和会话变化。
- 能保存、恢复音量配置；重启登录后恢复目标音量，并对稍后创建的会话应用规则。
- 提供可正常使用的 WPF 界面与后台托盘运行能力。
- 对可复现的音量异常提供经过测试的诊断与恢复操作；核心功能具备测试和日志。
- 能长期驻留，具有基本错误恢复能力，并能独立打包、安装和运行。
