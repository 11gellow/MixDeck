# 项目目标

> 规划基线：2026-10-20，用户提供《Windows Audio Manager 项目开发规划》（规划 V1.0）并要求纳入现有文档。原待确认的目标、技术栈和架构据此补充；2026-10-22 用户明确调整设备方案和自动保存行为，相关条目已更新。实施证据见验收文档。

## 定位与目标

- 项目名称：Windows Audio Manager（暂定）；类型：Windows 桌面音频管理工具；目标平台：Windows 10 / Windows 11。
- 当前工作目录仍为 `G:\c#_code\MixDeck`，不改名；工程名称沿用 `AudioManager`。阶段 1～3 已完成功能验收；阶段 4 配置模块功能已实现，真实重启登录验收等待用户反馈，进度见 [STATUS.md](STATUS.md)。
- 面向需要管理各应用音量、保存配置并恢复音量的 Windows 用户，增强原生音量混合器的管理能力。
- 解决的使用问题：重启后音量配置变化、显示值与实际效果可能不一致、异常时需反复拖动滑块，以及缺少便捷的音量快照、备份和恢复机制。
- 最终目标：稳定控制各应用音量，保存用户设置并按需自动恢复，减少配置丢失和重复手动调整。配置保存与恢复是主要功能，v0.4 是首个满足主要使用需求的版本。

## 核心需求与范围

| 功能领域 | 规划范围 |
| --- | --- |
| 核心音频管理 | 枚举输出设备、识别默认设备；从程序下拉选择设备时同步切换 Windows 普通播放默认输出，并确认实际结果；读取系统主音量及静音并调整主音量；枚举应用音频会话，读取应用名称、进程、音量和静音，独立调整应用音量及静音；识别同一应用的多个会话，处理退出后的会话消失 |
| 配置保存与恢复 | 读取可枚举会话，保存应用标识、音量、静音及输出设备信息；设备首次使用自动建立方案及原始快照，保留已有/导入方案和手动恢复，移除手动新建入口；按输出设备记住当前方案，默认输出切换时自动选择并恢复；前端或系统入口的用户音量/静音调节自动保存到该设备方案；启动及新会话自动恢复，无全局启用开关；多个方案；恢复回调、初始化及失败回读不得污染保存目标 |
| 事件监听 | 监听会话创建、状态、音量及静音变化，以及默认设备变化、设备连接与断开；新会话匹配规则；设备变化后重建设备与会话监听；避免自身操作造成重复处理和事件循环 |
| 异常诊断与恢复 | 记录 API 音量并比较目标音量，检测可观察异常；手动重新应用、重新获取会话及刷新状态；记录修改、恢复及 API 结果；失败日志与错误提示；实验验证相同值重设、改变后再恢复等操作的实际效果 |
| 图形界面与驻留 | WPF 界面显示主音量、输出设备及正在使用音频的应用列表；显示应用图标、名称、音量，提供独立滑块及静音；同级音量管理/高级选项页签、快照恢复入口和每设备方案管理；选择方案立即应用，规则和偏好隐式保存，无保存按钮；数值回车或失焦提交、Esc 取消，滑块拖动实时生效但松手保存，不锁定滑块；托盘驻留与菜单、开机自启、异常及操作反馈 |
| 配置管理 | 本地 JSON 与可扩展结构；稳定应用匹配，按需区分输出设备；导入与导出、恢复默认配置、用户偏好；处理损坏、缺失字段和版本变化，安全写入与备份 |

必须区分三类状态：**实时状态**来自当前 Windows 音频会话，**已保存快照**为创建方案时的回退基准，**目标状态**由每个设备当前方案的规则确定。用户从前端或系统实际调节音量/静音后自动更新目标并持久化；前端拖动期间实时生效，松手等待写入完成再回读保存，系统事件对其他目标照常保存；快照不变；启动枚举、新会话初值、恢复回调和失败回读不直接覆盖已有目标。

音频 API 返回的音量不等于最终听到的声音大小。应用内部音量、驱动和其他音频处理均可能影响播放效果；异常处理必须先复现、定位并验证策略，不承诺仅凭数值比较识别或修复全部音频异常。

## 不可随意改变的原则

- 保留 Windows 原有音频系统，通过其公开音频管理接口增强控制；不替换系统音频引擎，不依赖修改系统文件。
- GUI、业务规则和 Windows 系统调用分离；Core 不依赖 WPF 或具体音频封装，UI 不直接操作音频 API。
- 音量规则与设备控制分离，实时状态与持久化配置分离；不能仅以 PID 作为持久化应用标识。
- 事件回调不得阻塞 UI；正确管理音频资源、COM 对象和订阅生命周期，避免全局共享可变状态。
- 核心目标、需求边界、技术栈及重大架构变更须经用户确认，不能为方便实现而自行改变。

## 首个正式版本完成标准

- 能管理当前可访问的主要输出设备，读取并调整各应用音量，正常处理设备和会话变化。
- 能保存、恢复音量配置；重启登录后恢复目标音量，并对稍后创建的会话应用规则。
- 提供可正常使用的 WPF 界面与后台托盘运行能力。
- 对可复现的音量异常提供经过测试的诊断与恢复操作；核心功能具备测试和日志。
- 能长期驻留，具有基本错误恢复能力，并能独立打包、安装和运行。
